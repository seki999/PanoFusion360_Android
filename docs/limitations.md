# 已知限制

验收证据见 [testing.md](testing.md)。以下内容尚未完成或只在模拟器上验证过，不能视为已交付。

## 未完成 / 未验证

- **真机端到端验收未做。** 所有设备测试都运行在 API 35 x86_64 模拟器上。没有真实手持视频的拼接质量结论，也没有 arm64 真机的耗时与内存数据。
- **摄像头补拍未在真实场景中验证。** 视觉定位算法已用真实照片测试（关键帧、裁剪缩放视图、新视角、无关画面），但「通过 CameraX 预览实时定位并按指引补全项目」只能在真机上验证，模拟器摄像头只提供合成场景。
- **补拍前没有合并预览。** 新批次先完成真实重建，然后弹窗显示覆盖率变化，可选择保留或撤销（撤销会恢复上一版本并停用该批次）；不支持在提交前单独预览。
- **国际化只覆盖了一部分。** 首页和工程管理对话框有 zh/en/ja 字符串资源；工程详情、拍摄、导出页面，以及存入数据库的状态和错误文字仍是简体中文。

## 算法限制

- 每次最多融合 24 张关键帧，候选最多 360 张；每段视频不超过 3 分钟、4K 解码，工作帧最长边 1280（视频）/ 1600（照片）。清晰且不重复的帧超过 24 张时，按素材比例在时间上均匀保留 24 张（每个素材至少 1 张），其余标为「自动精简」并显示在关键帧列表中，不会静默丢弃。
- **长序列焦距漂移（待查）**：模拟器上 320×240、24 帧、约 169° 的合成平移，测得覆盖率 62.4%，而按几何约应为 28%，说明光束法平差可能把焦距估计得偏小。12 帧以内的场景与几何吻合（10.5% / 约 11%）。真实长视频的结果尚未核实。
- 原生渲染宽度为 2048 或 4096。导出不会超过渲染尺寸（只允许缩小），因此对相机拼接结果不提供 8192 输出；没有分块渲染。
- 完整单目 ERP 只识别明确的 Spherical Video V2（`st3d` mono + `sv3d/proj/equi`）。旧版 XML UUID、VR180、双目、cubemap 和 mesh 投影会被识别出来并拒绝，不进入处理流程。ERP 只选取最清晰的一帧，不做多帧融合，并在工作分辨率（最长边 1280）下解码。ERP 工程没有相机参数，所以补拍时不支持视觉定位。
- 视觉定位假设以纯旋转为主；如果手机平移较大、画面视差明显或纹理很少，定位会被拒绝（显示「尚未定位」）。每约 1.2 秒定位一次；两次定位之间的转向指引不使用传感器插值。
- 补拍时对全部启用帧做全局重建。锚点帧保持参考方向不变，但每次重建都会重新估计焦距，所以在两个版本之间，非锚点区域可能有细微变化。
- 质量图基于局部梯度和曝光，不是感知质量评价。没有专门的视差、重影或运动物体检测器；低纹理天空可能被标黄。
- 跨越 ±180° 经线的覆盖区域，「裁剪到有效区域」时保留全宽。

## 平台限制

- 处理在 WorkManager 前台任务中运行（API 35 为 mediaProcessing 类型，更早版本为 dataSync 类型），仍受系统配额、服务时限和温控限制。取消只在解码循环和原生阶段边界生效，单个 OpenCV 调用不能立即中断。
- 进程被杀后：WorkManager 会重新执行任务，已分析素材按检查点跳过，融合从头开始。如果任务不再运行，下次启动时工程标为「已中断」，并清理残留的暂存目录。
- `metrics.json` 中的峰值内存是进程的 VmHWM。在任务开始时尝试用 `clear_refs` 重置；如果内核不允许重置，记录值会包含任务之前的峰值（`peakRssResetAtJobStart` 字段会注明）。
