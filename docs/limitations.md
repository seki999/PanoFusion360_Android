# 已知限制（开发中）

- 尚未完成全部八阶段验收；当前测试结果以 testing.md 和构建日志为准。
- 默认每次最多 24 张有效关键帧，候选上限 360；每段视频限 3 分钟、最高 4K 解码，工作帧最长边约 1280/1600。超过预算明确拒绝，不静默丢弃。
- 普通全景默认原生渲染为 2048×1024；设置可选 4096，但尚未完成设备内存自适应。未提供 8K 或分块输出，不把低分辨率结果放大冒充高分辨率渲染。
- 完整单目 ERP 仅识别明确的 ISO BMFF Spherical Video v2 equi 与 st3d mono 标记。旧版 XML UUID、VR180、双目、cubemap 和 mesh 尚不支持。未知视频可由用户选择普通透视拼接，不依据 2:1 比例自动判断。
- 单目 ERP 先选择最佳完整候选帧，不做多时刻移动物体平均；当前解码仍使用工作分辨率。
- 补拍通过保留的原素材和启用关键帧全局重建。第一张启用帧作为方向锚点；禁用锚点或全局焦距重新估计可能改变参考，尚未实现锁定跨会话锚点内参。
- 没有实时视觉定位或定位后半透明叠加。摄像头明确显示尚未定位；传感器只提供辅助俯仰读数。
- 质量图依据局部梯度/曝光，尚非完整感知质量评价；尚未提供严重视差专用检测器、交互式参考方向修改或背景颜色选择。
- 可通过历史菜单恢复成功版本及其输入选择；已删除的源帧会阻止版本恢复。撤销批次通过重新融合真实素材实现，失败时保留上一结果并报告失败。
- 已使用 Hilt 和 ViewModel；尚未完成所有业务场景的独立 UseCase 拆分和全 UI 国际化，默认简体中文。
- WorkManager 前台 mediaProcessing（API 35）/dataSync（较旧 API）仍受系统配额、服务时限和设备温控限制。取消在解码循环和原生阶段边界检查，单个 OpenCV 调用不能立即中断。进程被杀后按素材检查点重启，融合阶段从头重做。
- 尚未做真机端到端验收；没有真实手持视频质量、峰值内存及长视频性能结论。
